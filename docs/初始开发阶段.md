## 8. Step C — pty 桥接 claude CLI

### 底层逻辑

cc-terminal 不重新实现 Claude Code 内核，而是**驱动 `claude` CLI 子进程**实现 1:1 能力对等。所有 slash 命令、skills、plan mode、sub-agents、hooks、MCP 自动继承。

### 后端

| 文件 | 角色 |
|------|------|
| `Cargo.toml` | +`portable-pty 0.8` + `uuid 1` |
| `commands/chat.rs` | 4 个命令 + ChatState（`Mutex<HashMap<sid, PtyHandle>>`） |
| `lib.rs` | `manage(ChatState)` + 注册 4 个命令 |

四个命令：
- `spawn_chat(cwd?, args?, rows?, cols?)` → 返回 `session_id`
- `chat_input(session_id, data)` → 写 pty
- `chat_resize(session_id, rows, cols)` → 调整 pty 尺寸
- `chat_kill(session_id)` → 杀子进程

读循环：`std::thread::spawn(|| { reader.read(&mut buf) ... })`，每段 chunk emit `chat:stdout` 事件；子进程退出 emit `chat:exit`。

### 前端

`features/chat/Terminal.tsx`：
- xterm.js + FitAddon
- `MutationObserver` 监听 `data-theme` 切 xterm theme（浅深双套）
- `ResizeObserver` 自动 fit + invoke `chat_resize`
- 状态行：启动中 / 已连接 / 已退出 / 错误
- 卸载时 `invoke("chat_kill")` + `term.dispose()`

### owner 意识发现的坑

切换到"用量"视图再切回"对话"，ChatView 会被卸载又重新挂载，触发 chat_kill 然后 spawn_chat，**上下文全丢**。

修复：AppShell 中让 ChatView 常驻 DOM，靠 `display: none` 切换可见性而不卸载。

### 验证

| 项 | 结果 |
|---|------|
| `cargo clippy -D warnings` | exit 0 |
| `pnpm typecheck / lint` | exit 0 |
| 启动 10 s 后无 stderr / panic | ✅ |

## 10. Step E — 会话管理

### CLI 调研

`claude --help` 确认：`--resume <uuid>` 是接续指定 session 的标志。

### 后端

`commands/sessions.rs`：
- 扫 `~/.claude/projects/<encoded>/*.jsonl`
- 不全量读：peek 头 64 行抓 cwd / firstTs
- file mtime 当 lastTs
- 全量行数当 messageCount（粗略）

第一次 clippy 报 `bind_instead_of_map` —— 我用 `and_then` 但总是返回 `Some(...)`，应该用 `map`。一行改完。

### 前端

`SessionsView.tsx`：
- 按 cwd 分组、按 lastTs 倒序
- 搜索 / 当前 session 高亮
- 「＋ 新建会话」按钮

### 切换机制

AppShell 持有 `currentSessionId`，传给 ChatView 作为 `key={resumeId}`。
- key 变化 → React 强制 unmount + remount Terminal
- unmount cleanup → chat_kill 旧 pty
- remount → spawn_chat 带 `args: ["--resume", resumeId]`

天然解耦 + 不需要新加状态机。
